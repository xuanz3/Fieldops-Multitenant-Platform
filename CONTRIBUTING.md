# Contributing

## Workflow

1. Link work to a GitHub issue.
2. Create a focused branch such as `feat/12-tenant-context`.
3. Use Conventional Commits.
4. Keep commits small, complete and buildable where practical.
5. Open a pull request with testing, risk and evidence notes.
6. Merge only after required checks pass.

## Commit examples

- `feat(api): add tenant context middleware`
- `test(domain): cover invalid work order transitions`
- `docs: record PostgreSQL decision`
- `ci: validate backend and frontend builds`

Avoid messages such as `update`, `changes`, `final` or `fix stuff`.

## Definition of done

- Acceptance criteria are met
- Relevant automated tests pass
- Documentation is updated
- No secrets or personal information are present
- Known limitations are recorded
