# Contributing

## Workflow

1. Open or link an issue describing the change.
2. Create a focused branch.
3. Use a clear Conventional Commit message.
4. Add or update relevant tests.
5. Open a pull request and record the validation performed.
6. Merge only after all required checks pass.

## Commit examples

- `feat(api): add work-order filtering`
- `fix(auth): reject expired access tokens`
- `test(data): verify tenant relationship constraints`
- `docs: clarify production deployment`

Avoid vague messages such as `update`, `changes`, `final` or `fix stuff`.

## Completion criteria

- Acceptance criteria are met.
- Relevant automated tests pass.
- Documentation is updated.
- No secrets or personal information are present.
- Known limitations are recorded.
